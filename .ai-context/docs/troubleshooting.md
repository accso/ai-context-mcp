# Troubleshooting — Full Reference

For the two most common issues, see [`README.md`](../README.md#troubleshooting). This doc covers every documented issue in full.

## "Shared infrastructure not running"

```bash
mise run ai-context-infra-up
```

Starts (or confirms already running) Qdrant, PostgreSQL, and the shared, mandatory `ai_context_inference` service (embeddings + re-ranking).

## L1 summaries not generating

- Check LM Studio (or your configured `llm.provider`) is running with the server enabled
- Or switch `llm.provider` to `ollama` in `config.yaml`

This is no longer an embedding-related failure mode: embeddings are generated by the shared, mandatory `ai_context_inference` service (`.ai-context/inference/`), not an external, user-managed process. If embeddings themselves seem to be failing (indexing errors, `semantic_search` returning nothing), check the inference container instead:

```bash
docker ps --filter name=ai_context_inference        # is it running?
docker logs ai_context_inference                     # startup/model-load errors
docker inspect -f '{{.State.Health.Status}}' ai_context_inference   # healthcheck status
```

If it's missing entirely, start it with `mise run ai-context-infra-up` (it's part of the same always-on infra tier as Qdrant/PostgreSQL now, no separate opt-in).

## L1 summary contains `<think>…</think>` text or is very slow (thinking model)

The summariser strips thinking blocks automatically, but if LM Studio is running a thinking model (Qwen3-thinking, DeepSeek-R1) the CoT phase still adds latency. Add to `config.yaml`:

```yaml
shared:
  llm:
    disable_thinking: true
```

This adds `/no_think` to the system prompt and sets `thinking_budget: 0`, suppressing CoT entirely.

## Qdrant collection not found / project not registered

```bash
mise run ai-context-reset   # full wipe and re-init from scratch
```

## When do you need a full re-index?

1. **First-time setup** — handled automatically by `mise run ai-context-up`.
2. **The watcher was down for a while** — no longer requires a manual re-index. On the next `mise run ai-context-up` the watcher's startup sequence automatically detects and re-indexes any files that changed while it was stopped (SHA-delta reconciliation), checks Qdrant/DB vector parity, and backfills any missing L1 summaries. A full reset is only needed if many files changed AND the backup restore path is preferable for speed.
3. **You changed the chunker / L2 logic** — existing chunks were built with the old logic; re-index rebuilds them correctly.
4. **You rebuilt the inference service with a different embedding model** — the model is hardcoded (see [Architecture Deep-Dive — Embedding service](architecture-deep-dive.md#embedding-service)), so this only applies if you've edited `inference/main.py`'s `EMBEDDING_MODEL_NAME` and rebuilt the image; all existing vectors are then incompatible and a full re-index is required.
5. **You changed `config.yaml` skip list or file filters** — re-index applies the new rules cleanly.
6. **The Qdrant collection or PostgreSQL was wiped** — full re-index needed (or restore from backup if available).
7. **You suspect index corruption** — full re-index is the nuclear option; the self-healing Qdrant parity check on startup may handle common cases automatically.

```bash
mise run ai-context-reset
```

## Check watcher or MCP server logs

```bash
# watcher logs (all projects share one watcher container)
docker logs -f <repo-slug>_context_watcher

# MCP server logs (all projects share one MCP container)
docker logs -f <repo-slug>_context_mcp

# all running ai-context containers
docker ps --format "{{.Names}}" | grep "_context_"
```

## Upgrade the DB schema (after pulling a new version that changes `init.sql`)

```bash
mise run ai-context-down                        # stop MCP servers + watchers first
mise run ai-context-infra-down -- --wipe           # stop DB and wipe all data volumes
mise run ai-context-infra-up
mise run ai-context-reset
```
